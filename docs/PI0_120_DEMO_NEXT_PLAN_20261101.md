# π0 下一轮：接触设置核验后的 120 条示范长训练方案

日期：2026-11-01。状态：**方案，未执行新训练**。依据为本轮四个失败任务的实际诊断，详见 `results/piper-color-v1/pi0-failure-diagnosis-20261101/REPORT_zh.md`。本方案更新此前只依据六条示范制定的进入下一阶段条件。

## 决策及依据

120 条示范的长训练适合作为下一轮主线，但应先固定仿真接触版本并重新生成匹配的训练观测。原因有三层：前期对准和闭环状态偏移、原软接触配置的持续滑移、缺少失败恢复示范。增加训练量主要针对策略拟合与布局覆盖，不能直接消除数值接触滑移，也不自动提供恢复动作的监督。

不再把“先在原六条上达到两次 6/6”作为启动 120 条的硬门槛。教师接管到抓取/抬升阶段后原失败任务分别达到 6/8、8/8，说明完整动作链可执行；而原环境下理想教师抓取静止十秒也会掉落，继续只用六条追求满分可能混淆策略学习和仿真问题。

## A. 先冻结仿真与数据版本

候选配置为 `cone=elliptic, impratio=10, noslip_iterations=0`。其余摩擦系数、夹爪力限、控制器、相机、步长及成功条件沿用原定义。选择依据是教师抓取的十秒静态保持和完整回放，而非寻找能最大化旧策略成功率的参数。NoSlip=3 只保留为诊断对照。

- 本轮已观察到 `impratio=10` 下教师十秒保持 6/6；正式实现候选版本时仍需保存场景 XML、哈希和独立版本号，核对六项完整教师回放。
- 原 v1 的数据、模型、2/6 与 2/6 成绩及全部轨迹保留。候选 v2 下冻结旧策略为 4/6 与 1/6，这些是环境干预结果，不能记为新训练收益。
- 重新生成 **120 条训练示范**，保留原训练布局 100–139 和红/绿/蓝三个指令。记录实际反馈、实际发送的命令、两路 RGB 和时间戳；不复用旧环境的图像/状态与新环境的动作混合成样本。
- 保留验证布局 1000–1004，共 15 项任务；测试布局 2000–2009，共 30 项任务。验证/测试在同一个冻结候选环境中评测，训练不读取它们的示范或统计量。
- 新目录及归一化资产与 v1 隔离。归一化只使用新 120 条训练数据，并按 horizon=10 的真实动作块和尾部填充计算。

这些核验只确立仿真的内部一致性，不代表真实 Piper H 的摩擦、夹持力和控制响应已经标定。

## B. 固定训练配置

| 项目 | 计划 |
|---|---|
| 初始化 | 官方 `pi0_base`，独立新 run，不接续六示范的 2010 参数 |
| 模型 | JAX Pi0，`pi05=False`，连续状态输入，mean/std 归一化 |
| 微调 | 保留现有 LoRA/freezing 配置；不同时修改视觉编码器冻结策略或启动全参数对照 |
| 数据量 | 120 条，40 个布局，预计 32,160 个观测起点；以实际生成清单核实 |
| 输入/输出 | 双 RGB、实际关节/夹爪反馈、语言；六关节相对状态增量、夹爪绝对开口 |
| batch / horizon | 4 / 10 |
| 控制 | 20 Hz，每次执行 5 个动作，评测上限 420 步 |
| 初始化及抽样种子 | 42；保存每轮排列、优化器、训练步数和 RNG |
| 学习率 | peak 3e-5，warmup 100，cosine decay 预先固定到 24,120，末值 3e-6 |
| 总候选预算 | 最多 24,120 updates，约三轮起点遍历；分段依据闭环证据决定推进 |

批次 4 下，8,040 updates 为一轮，16,080 为两轮，24,120 为三轮。不要在阶段暂停/恢复时重新启动 warmup 或缩短 decay 时间轴。

## C. 分段评测与推进条件

先在候选 v2 上补测冻结的六示范旧策略在 15 项验证任务中的结果，作为同环境基线；不能直接把已有 π0.5 的验证数字当作 π0 基线。

| 更新节点 | 训练布局诊断 | 验证评测 | 用途 |
|---:|---|---|---|
| 2,010 | 原六项 × 两种子 | 15 项 × 两种子 | 观察接近、抓取与抬升是否开始改善 |
| 4,020 | 同上 | 同上 | 检查改善是否持续、是否出现阶段退化 |
| 8,040 | 同上 | 同上 | 第一轮遍历后的决策点 |
| 16,080 | 同上 | 同上 | 有闭环改善时继续到第二轮 |
| 24,120 | 同上 | 同上 | 本计划最高预算，冻结候选后另做测试 |

评测基础种子固定为 42、43，每项独立 seed = base + layout×3 + color_index。两套种子的结果全部报告。每个布局的三个颜色相关，保留布局分组，不把重复种子当作额外独立布局。

主要指标仍是完整任务成功：正确目标入盒、无错误目标入盒、夹爪开口大于 0.08 m、干扰物位移小于 0.025 m、关节越界小于 0.01 rad，且全部条件持续两秒。

辅助指标包括：抓取时物体相对夹爪偏差、有效双指夹持、抬升成功率、持物到盒上方的比例与耗时、掉落次数、掉落后重新接近/张爪/抬起的行为、入盒后松爪情况。记录视频和真实执行命令，教师接管及修改物理条件的诊断结果单独列出。

到 8,040 时，如果完整成功和验证表现持续改善，可按同一时间轴继续；若只见损失下降而抓取偏差、持物失败及两套种子的闭环成绩没有改善，应先检查轨迹和数据覆盖，不能把剩余预算自动消耗完。出现数值异常、错误动作或评测执行异常时保存记录并停止相应阶段。

候选只依据验证结果选择；独立的 30 项测试在配置与候选冻结后执行，不反复用测试集选模型。

## D. 掉落恢复与后续数据

本轮核对全部 120 条示范后，均是相同的九阶段成功教师流程，没有显式的掉落/再抓取分支。因而这一轮 120 条长训练主要验证正常任务的准确性和稳定性，不能承诺学会恢复。

若候选接触版本和长训练后仍有未抓住、边缘夹持、掉落后空手搬运等失败，下一数据增量应覆盖这些具体状态：抓取前位置偏差、刚触及但未夹住、抬升时持物偏移、物体落回桌面。用真实仿真反馈重新规划教师纠正动作并保存实际命令，不把未来状态、物体坐标或阶段标记输入策略。先在原四项失败任务的受控扰动上验证示范有效，再纳入训练；恢复轨迹和正常轨迹的比例作为单独变量。

## E. 资源、日志与可复现性

- D57 的 Pi0 和颜色仿真环境继续隔离；MPC-RL 与 SuperMimic 作业保持各自环境。沿用 JAX 不预分配、0.50 内存比例和现有 CPU 限制，正式启动前再次核对资源。
- 按此前约 0.49 秒/update 粗算，8,040 的纯更新约 66 分钟，24,120 约 3.3 小时。考虑更大数据集的读取、保存、两种子评测及共享资源，首段暂预留 **2–3 小时**，全三段约 **4–6 小时**；数据重生成另由前六条实测估算。启动后的前 100 次更新重新估算速度。
- 每一次更新记录数值与耗时，每 500 次及评测节点提交日志。保留有限重试与待补传记录，网络上传异常不直接中断训练。
- 完整检查点保留最近两个及固定评测节点，逐次日志全部保留。每个完整检查点约十余 GB，不能把 48 个 500-step 检查点永久堆积在当前磁盘；运行前落实保留规则和空间预算。
- 保存完整模型、优化器、RNG、采样位置、配置、归一化、场景版本、数据清单和代码提交。训练与模型评测顺序执行，避免同时加载两个大模型。

本计划联合改变数据覆盖和训练预算，属于下一轮工程验证。若之后需要回答“收益究竟来自更多布局还是更多更新”，再增加同预算、同 schedule、从 base 重新初始化的六条/120条配对对照；本轮诊断不能替代这一归因实验。
