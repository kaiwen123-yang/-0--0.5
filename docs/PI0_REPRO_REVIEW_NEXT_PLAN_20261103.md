## 3. 回到论文与官方实现

### 3.1 当前优化目标与完整任务成功不是一回事

π0原论文§IV–V把问题写成以图像、指令、机器人状态为条件的动作块分布学习，并区分广覆盖预训练与流畅一致的后训练。论文也明确说明数据组成与权重仍有开放问题；它没有规定本项目应当使用24条纠偏或10%混合。

[π0原论文](https://www.pi.website/download/pi0.pdf)，§IV–V、§VII。

用户实际调用固定版本 `Pi0.compute_loss`。其时间约定可写为：

`x_t = (1-t)·A + t·epsilon; target = epsilon - A`

模型学习带噪动作上的流速度，推理再积分生成动作。该版本时间方向和原论文的一种写法相反，但训练目标与采样积分配套一致，不是符号移植错误。

实际7维动作先归一化并填到32维，loss对32维流速度误差取均值，再对批次和时间取均值。这沿用官方代码，不能把25个补零维没有mask判为用户新引入的bug。相应地，总loss既不是7维机械动作误差，也不是抓取或完整任务成功率。

依据：[官方compute_loss和sample_actions](https://github.com/Physical-Intelligence/openpi/blob/215abfb217dbac7d5f1273282331b9b1866c0479/src/openpi/models/pi0.py)、[官方train_step](https://github.com/Physical-Intelligence/openpi/blob/215abfb217dbac7d5f1273282331b9b1866c0479/scripts/train.py)。

### 3.2 π0.5与当前任务适配的距离

π0.5原论文的关键包含异构数据联合训练、高层语义与低层动作、离散预训练和连续动作后训练；后训练保留文本与视觉相关监督以维持能力。它不是简单把π0换个模型名再做少量颜色示范。公开openpi固定版本也明确只支持π0.5的flow-matching动作头训练和推理。

[π0.5原论文](https://www.pi.website/download/pi05.pdf)，§IV及§V；[固定版本README](https://github.com/Physical-Intelligence/openpi/blob/215abfb217dbac7d5f1273282331b9b1866c0479/README.md)。

本项目可以准确称为“使用π系列公开预训练模型进行任务迁移与微调复现”。大规模异构训练、跨家庭泛化和实机长时任务尚未复现。此时切换π0.5不会自动解释或解决π0继续训练造成的退化。

### 3.3 时域是设计变量，但当前没有证据要求统一改掉replan

π0论文Appendix D使用50步预测，并在20Hz机器人执行16步后重规划。当前10步预测、每5步重规划是任务适配设置，不是原论文原样配置；官方LIBERO适配也采用短动作块。不能仅因与论文不同就改成50步。

当前已保存的chunk分析是：

- 前5步切片与保存raw动作的最大差值为0；
- “闭爪只在未执行后半段出现”在成功202/211、失败26/29中都出现；
- 某些严重迟闭爪失败在闭爪前没有或只有一次这种现象；
- 推理等待期间物理暂停，墙钟推理延迟不能解释这批仿真中的迟闭爪。

因此没有发现前5步取错的程序错误；tail现象也不是普遍失败判据。此结论不等于执行限速、物理反馈或所有时间策略都已被证明正确。已完成的分析不再列为下一轮重复任务。

[π0原论文Appendix D](https://www.pi.website/download/pi0.pdf)、[本轮trajectory_diagnosis](https://github.com/kaiwen123-yang/-0--0.5/blob/c912dc5efbbec7dce53361fe989bf71eac0b2351/results/piper-color-v1/pi0-ef-local-20261102/trajectory_diagnosis.json)。

| 优化器 | 保留B全部状态、moment与计数，不重置其余参数 |
| 模型/部署 | π0，连续状态，原norm与动作定义；horizon10，replan5，20Hz |
| 任务判据 | 原v2场景，420步总时限、连续40步完整成功 |
| 唯一干预 | SigLIP参数最终更新为0；其余参数更新规则与E一致 |

`E/sample_order.json`有4000项，可直接转int64 NPY。这是格式转换，不是重建采样；G只消耗前2000项。数据用 `PiperDataset(DATA, "train", 10)` 即可：旧 `CombinedDataset` 会无条件打开F纠偏目录，G无需继承这个无关依赖。

### 5.3 冻结方式必须保持对照含义

本轮采用**最终更新投影**：

1. 按E原filter、原dtype恢复B完整状态。
2. 沿用官方梯度计算、全局梯度裁剪与AdamW更新。
3. 在 `tx.update` 之后、`apply_updates` 之前，把 `PaliGemma/img/.*` 的最终update置零，其他update原样应用。

这能阻止已有Adam动量或weight decay继续移动视觉权重。只把视觉梯度设零不能保证这一点。

不要直接更改freeze_filter再强行恢复：这会改变optimizer树，而且官方初始化可能把新增冻结参数转bfloat16，从而引入另外的变量。可在项目自己的G训练入口用现有 `nnx_utils.state_map / PathRegex` 实现更新投影，不改共享openpi安装、模型环境或依赖版本。

视觉梯度和其optimizer buffer仍计算并更新，这是为了保持E的裁剪和优化器结构；**实际视觉权重保持B值**。它不是节省反向计算的实现，也不能将原468M梯度参数数目全部称为“有效更新参数”。只在正常训练配置/报告中记录gradient_parameters、effective_update_parameters与被固定模块，不添加权重逐元素扫描、哈希、差分测试或额外试跑。
