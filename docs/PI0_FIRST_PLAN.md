# π0 优先的仿真与实机计划

日期：2026-10-31。按用户本轮倾向，后续优先级为 **π0 仿真任务 → π0 实机数据与闭环 → π0.5 同条件比较**。本文件为下一轮训练方案，尚未启动新训练。当前旧 π0.5 LoRA 仅用于验证共用的数据、动作、仿真和模型服务接口。

## 已完成的依据

[本轮结果索引](../results/piper-color-v1/d57-recovery-20261031/index.json)。旧 LoRA 在 D57 两次完整验证分别 3/15、0/15，训练布局 100 为 1/3；每步重规划的验证布局 1000 为 0/3，逐任务独立种子的同布局为 1/3。上述小范围调度探针不混入完整验证成功率。

原示范动作回放 6/6 完成。先由教师执行到抬升结束（112 步）或释放开始（178 步），再交给旧策略的 6 个介入实验全部完成；它们不是策略自主成功。第一轮 12 个失败中，5 个未把指定物体抬高 5 cm，6 个抬起后未将物体送到盒子水平范围内，1 个曾到达盒子上方但未完成完整条件。因此，优先检查和改善抓取准确性、持物搬运与离开示范轨迹后的行为；不能把统一增加松爪命令作为解决办法。

D57 对一个完全相同的保存观测重复推理、包括换模型进程，输出一致；它与历史 fy-5080 输出存在数值差异，尚未完全归因。完整闭环对细微差异敏感，历史 0/15 和新两轮结果均保留。后续每任务使用独立随机种子，防止先前任务的提前终止改变后续任务的采样序列；这不保证接触仿真的逐位确定性。

## 第一步：π0 专用配置和小规模完整任务学习

- 从官方 `pi0_base` 初始化，使用 JAX LoRA。新建 π0 配置，`pi05=False`，使用 π0 的连续状态输入和对应归一化变换；不能只替换 π0.5 权重路径。当前代码的 `make_config` 仍是 π0.5，本项尚待实施和真实训练验证。
- 第一版保留现有 20 Hz、horizon=10、每 5 步重新规划、六关节 rad 加绝对夹爪开口 m 的接口，以便复用仿真与将来的示教数据。horizon=10 是本任务适配选择，不宣称等于论文所有实验的设置。
- 开发子集为训练布局 100、101，各三个颜色，共 6 条完整示范、1,608 个观测起点。batch=4，首段 2,010 updates，约 5 轮起点遍历；只用该训练子集重新计算统计量。
- 初始学习率沿用 3e-5、100 步 warmup；这一小数据开发 run 独立保存，不作为后续完整训练的初始权重。保留完整模型、优化器、随机状态和配置。
- 每 500 步及最后一步保存，实际闭环评估这 6 个完整任务。开发目标为六个任务都能完成选色、抓取、入盒、松爪和连续 2 秒保持，并在第二个预先固定种子下复查。它只是流水线与学习能力的开发门槛，不是泛化成绩。
- 若训练布局仍无法完成，先根据轨迹区分动作映射、控制响应、拟合不足和闭环偏移；停止扩大数据或同时启动全参数训练。

## 第二步：π0 全部合成训练集

| 项目 | 计划 |
|---|---|
| 数据 | 原 120 条训练、15 条验证、30 条测试；布局划分不变 |
| 初始化 | 官方 pi0_base，全量训练数据重新计算归一化；与小数据开发 run 分开 |
| 主要方法 | JAX LoRA；实际可训练参数量和峰值显存由运行记录 |
| 首段预算 | batch=4，8,040 updates，约一轮训练起点遍历 |
| 后续预算 | 仅在闭环证据支持时扩展，预设最高 24,120 updates，约三轮；不自动启动 |
| 学习率 | 拟用 peak=3e-5、warmup=100；完整 run 预先固定 decay_steps=24,120，阶段暂停时不改学习率时间轴 |
| 验证节点 | 2,010、4,020、8,040；继续时 16,080、24,120。按验证表现选候选 |
| 评测随机性 | `--seed-scope episode`；seed=42 + layout_seed×3 + color_index，记录实际种子 |
| 保存恢复 | 每 500 步及阶段边界保存完整 optimizer/train_state；先验证真实恢复，再进行长阶段 |
| 最终测试 | 配置和候选冻结后才运行独立 30 条测试，不按测试结果挑模型 |

1500 updates×batch 4=6000 个训练起点，约为原 32,160 个训练起点的 0.19 轮。训练覆盖不足是待检验假设，不是已证明的唯一原因。训练是否需要更多示范、阶段采样或纠偏数据，由上述闭环结果决定。

主要指标为完整任务成功率、抓取失败、持物搬运失败、放置/释放失败、其他物体扰动和关节超限；同时记录推理延迟与训练资源。各阶段指标不替代完整成功率。每布局三个指令相关，统计和报告保留布局分组。

D57 共享同一 GPU。实际执行先记录现有 SuperMimic、MPC-RL 占用；使用本项目环境，不停止或改动其他任务。训练时关闭 JAX 预分配，并从该真实训练 run 的前 100 updates 测量速度和显存，再估算余下预算。已有约 1 秒/update 的历史记录仅用于粗估，不能当作共享 D57 的速度承诺。

## 第三步：实机数据与部署

仿真推进期间可准备采集接口。设备可用后，先核验 Piper H 固件、CAN、关节方向/零位、夹爪行程、双相机与时间戳，并做低速跟踪和示教回放。观测使用从臂真实反馈，动作保存真正下发给从臂的目标命令。

先采集同一颜色入盒任务的真实示范，建立按布局/采集时段分开的验证数据，再做实机微调、影子推理和低速闭环。真实数据尚未就绪时，继续完成仿真与数据链路；合成数据微调成功不作为实机完成标准。另行测量不暂停物理时钟时的采集、网络、推理、动作缓存和执行时序。

## π0.5 的后续方案

π0.5 暂缓新训练。待 π0 流程和真实数据就绪，使用相同任务、观测动作语义、数据划分和评测协议，从 pi05_base 独立初始化 LoRA，再与 π0 比较。沿用按遍历量安排的阶段预算和验证选择；全参数微调只在 LoRA 与数据诊断提供依据后安排。旧 LoRA 无优化器，旧全参备份不完整，均不作为可无缝续训的检查点。
