## 已完成的标定如何使用

沿用 `results/calibration-audit/20261122/ssh_multiview/wrist_rgb_calibration.json`。本批为 35 个训练、7 个开发、9 个冻结后独立验证姿态，固定 `k3`；完整 received RGB 网格的数值逆映射检查通过。九独立姿态的固定板全链像素误差均值 2.222 px，板位姿平移偏差均值 3.342 mm、P95 5.354 mm，旋转均值 0.445°。P95 平移并未小于早期 5 mm 参考值；这些指标也不是外部绝对抓取精度。

标定适用于当前腕部安装、640×480 分辨率及原始 received 图像处理链。默认不重做标定，不改已有 K/D/X。π 输入仍为原始接收 RGB，按既有模型预处理；不额外悄悄去畸变。新模型的同 K 理想图上有 5,744 个输出像素对应的采样落在原图之外，若以后生成去畸变图需另定 ROI/边界处理；这不等于 received 域求逆失败。

手眼参数负责相机与法兰的几何关系，不提供任务动作标签，也不会直接把基础权重变成本机策略。当前 joint-action 任务不需要因 SDK 夹爪坐标命名问题重做手眼。安装或图像链改变时重新评估适用性；精密放置、深度投影、工作区外推则需要相应空间验证。

## 正式采集前的两项实现

### 1. 第七维统一为本机 SDK 宽度坐标

现场测量已经表明 SDK 宽度与当前指垫物理净距不同。例如张开目标 40 mm、稳定 SDK 反馈约 39.5 mm 时，指垫净距约为 35 mm；闭合端和中间点的差值也不相同。证据见 [指垫测量记录](../results/pi-readiness/20261123/local_commissioning/pad_clearance_2134.json)。

首版正式契约采用 **`gripper_basis=piper_h_sdk_width_m_v1`**：

- `state[0:6]`：六轴实测关节角，rad；`state[6]`：原始 CAN 反馈的 SDK 宽度，µm 转 m。
- `action[0:6]`：实际主机提交的六轴绝对目标，rad；`action[6]`：实际提交的 SDK 绝对宽度目标，µm 转 m。
- 指垫净距另存 `pad_gap_m` 和测量位置、工具、条件，不改写 state/action，也不将稀疏测点硬拟合成通用偏置。
- 夹住物体时目标与反馈可以不同。A01 的闭合目标 15 mm、反馈约 24.6–24.8 mm 应分别保留，不能互相覆盖。
- 前六维在模型内相对 chunk 起始 q 做 delta，推理只恢复绝对目标一次；第七维继续为绝对值。

同机行为克隆可以使用这个一致的设备坐标，不需要先拟合全行程物理净距曲线。需要的是将契约版本贯通 **正式 setup、采集、导出元数据、训练资格检查、norm/run spec、policy metadata、推理适配及现场唯一发送端**，明确它对应本机夹爪与安装。

现有 `prepare-pads` 配置和 replay 分支明确限制 commissioning；`dataset.py` 与 `policy_config.py` 仍有 `total opening` 的旧描述。下一轮应完成这项小范围语义与资格检查修改，再建立新的正式 setup。**不得只改 `commissioning_only` 或 `training_eligible` 标志，不得回改旧 A01 的资格。** 当前 A01 无 train split，现有训练入口已经挡住它；这项修改也不是要求新建通用校验框架。

### 2. teach / plan / replay 正常结束于释放后抬离

正式任务应明确结束于 **`post_release_retreat`**：方块已放入浅盘、夹爪已经打开、末端已经抬离并稳定。回起点是下一次准备动作，放在任务 episode 之外。

A01 现有选定抬离端点保留了源轨迹和原图证据，但对应 `retreat_window` 分支目前仅允许 reviewed commissioning。下一轮应让 teach 正常记录该终点，plan 使用该正常范围，replay 在该点完成并保持；不把不合适的后续手拖回程纳入成功示范，不仅删除现有 formal 限制。

**新源示教结束的首次模式交接与首次回起点仍是明确的待实现阶段。** 示教可能停在非零的抬离姿态。现场必须先核对现有 SDK 对退出示教、模式切换和目标接管的实际能力，保持新鲜反馈与原目标来源，再实现到首次 empty 起点的合法过程。当前依赖“已有成功 empty”的 `return-start` 不能直接作为第一次 empty 之前的 reset 方案；不能补造空场成功记录，也不假定一条回起点命令可处理这个先后依赖。

默认最小方案是在真实抬离点 E 封存任务窗口后，操作者仍处于被动示教模式，完成单独人工重定位；原始反馈标记为 reposition_only，任务 end 不变。进入已验证的健康近起点范围后再退出示教、读新反馈，复用近零交接与同位锚定。若需近起点短回程，先核对测试机22:07实际代码和本次适用条件，不能将那次短回零推广成远位自动返回。现有 restart-teach 限定 commissioning，新的正式合同接续需要有针对性的实现与现场验收。

完成新源的首次准备后，先对该源执行空场核查，再进行实物重放。后续 reset 独立记录，不混进训练任务窗口。新源路径变化需要相应空场证据，不把旧 A01 空场通过扩展到所有新源。

## 正式采集与划分安排

首个任务继续使用轻质、易夹取、不易滚动的物体放入浅盘。固定腕相机、底座、任务语言和物体类型；浅盘先固定，在已核实工作区内改变物体位置和朝向。固定条件与每次变化均记录，不把同一路径重复几十次当作同等数量的独立覆盖。

当前导出器分别要求 `session_id`、`placement`、`source_trajectory_id` 不跨 train/validation。因此，**同一个 session 即使有不同布局，也不能一部分 train、一部分 validation**。开始正式采集前就按 split 创建真实独立会话，避免临到导出才发现无法分组。

下面是 50 条预算的可执行示例，并非固定指标：

| 真实会话 | 用途 | 成功条数示例 | 布局与源轨迹 |
|---|---|---:|---|
| T01 | train | 20 | 多个 T01 前缀布局，实际重新示教的源轨迹 |
| T02 | train | 20 | 多个 T02 前缀布局，记录本次会话真实来源 |
| V01 | validation | 10 | V01 前缀的新布局、新示教源轨迹；不复用训练源 |

每个会话的真实生成 ID 和每条原始来源要保留。不能仅改 JSON 中 ID 制造独立性，也不能按帧随机拆分。若同一源重放多次，它们必须在同一 split 内，并如实记录源重复关系。两模型使用相同划分；norm 只使用 train。验证集用于模型选择，阶段 F 的实机新场景不混进这次训练或验证数据。

既有 [本地示范指南](PI_LOCAL_DEMONSTRATION_GUIDE_20261123.md) 可作为已部署操作背景；涉及新正式契约、正常抬离结束和首次交接时，以本文件、A01 审核与后续执行提示词为当前目标，先落实实现后再给现场完整命令。

## 固定图像与时间约定

唯一真实图像仍为 DC1 `CC16762023M`，`camera_mount=wrist`，模型槽 `left_wrist_0_rgb`，其余槽 `mask=False`。

现有数据接口是 20 Hz 网格、10 步 action chunk：每行相差 50 ms，约覆盖 0.5 s；它们不代表已测得模型推理速度。观察取网格 t 之前最近收到的 RGB、完整关节组及夹爪反馈；action 取 `(t,t+50ms]` 末的完整有效提交目标。保留每行来源时间和目标 ID，不把接收时钟关联写成曝光同步。

末尾 chunk 重复同一 episode 的最后动作，不跨到另一 episode。目标请求、实际主机提交和反馈分开保存；提交成功不等于控制器执行到位。较早发出的持续保持目标也不能仅因年龄大就被当作失效反馈。后续策略调度必须与训练动作的时间语义一致。

## 现场控制适用范围

现有 A01 证据已经覆盖其受控源轨迹的空场与实物重放。它不证明任意在线策略、网络超时、一般碰撞场景或 action-chunk 调度已经验收。当前 `infer.py` 对保存的 NPZ 推理且 `sent=false`；`live_view.py` 的落盘 CSV 也不是实时控制反馈源。

正常结束保持已确认姿态及已有夹爪目标，并保留其来源；不把实测夹爪开口回灌成新目标，不盲目失能或回零。暂停、异常停止与新路径执行只按现场已核实的接口衔接，不将静态脚本的逐点到位等待塞进每个 50 ms 动作点。手拖期间停止主机发目标；退出示教后的接管按前述首次交接阶段核实。

继续只读复用 dog-and-arm 的既有 H0/SDK 能力；新增契约、任务采集和转换改动保留在 π 仓库，不改共享 SDK，不新增竞争 CAN 发送进程。上次记录的使能、模式和姿态是历史快照，下一次动作前由现场读取当前状态。
