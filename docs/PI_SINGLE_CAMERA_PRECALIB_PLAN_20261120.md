## 2. 对旧计划的修正

1. 11-16 的“B 双 RGB 齐备才完成 R0”不再是当前路线。B 仍是历史双相机仿真基线，保留权重、原 norm 和结果；不将改变输入后的模型称为原 B 同条件结果。
2. 新接口只接受一个真实 camera_rgb。固定外部相机使用 base_0_rgb；腕部安装使用 left_wrist_0_rgb。其余槽 mask=False，协议中的零张量只是无效槽占位，不冒充第二路真实图像。
3. π0 和 π0.5 的准备同步推进，不把 π0.5 配置工作延后到所有 π0 实验完成。两个完整训练任务是否同时占用同一 GPU，按真实资源证据决定，不自动改成 LoRA。
4. 数据采集、时间关联和接口准备可以在手眼标定之前完成。标定结果到位后作为同一会话/数据版本的外参资产接入；当前关节策略并不需要把手眼矩阵直接拼进 state。
5. 标定通过不等于训练数据齐备或模型已经能自主抓取。静止图像与反馈没有真实动作监督，不能拿去冒充示范。

本轮只负责 π 系列实机。dog-and-arm 的 P0–P3、M1、开门和底盘开发不在范围内。

## 4. 标定板到货前：六项并行工作

### A. 固定唯一相机的实际身份和视野

记录型号、序列号、物理安装、RGB话题、分辨率、色序、CameraInfo、图像是否已去畸变、曝光/白平衡的实际设置、支架与线缆情况。固定当前实际部署会使用的安装，保留一张安装照和一张未加叠字的原始图。

不要因为历史ROS命名为 /wrist_camera/... 就把外置相机改名或判成腕部。保持现有正常发布者，采集端订阅实际话题。

先看物体、夹爪、工作桌面在实际视野内的覆盖。标定前可以检查这些事实；不能凭空声称全工作空间都已可见。

### B. 复用 H0，实际记录与显示

继续使用已验机的相机启动、ROS/DDS环境与 pyAgxArm 接收器，一个相机采集源供记录和显示使用。新 viewer 订阅已有ROS图像并读取H0反馈，不打开第二个相机pipeline，不发CAN。

现场完成一段有明确边界的连续只读记录，默认180秒；前面已产生符合条件的实际会话可复用。需要连续原图时，显式选择完整bag或H0的 sample-period=0，不把默认5秒抽样当成30Hz图像数据。原始大数据留原机器，不进入Git。

viewer 明确区分：

- 本viewer收到的RGB帧龄。
- H0反馈的原始接收时间。
- 最近已写盘反馈的年龄及文件可见延迟。

没有真实反馈显示“未收到”，不用上一条目标或零值填补。当前不发动作，记录里 action=null，training_eligible=false。

### C. 时间关联与动作语义

新增 associate_h0.py 读取H0原始时间表和实际图像索引，用同机同一boot的单调接收时间关联图像、关节、夹爪，保留ROS header、SDK与内核时间原值。

关联策略与允许年龄显式记录；不能用未来反馈假装在线时可用。分别报告：

- 全部RGB接收事件及时间间隔。
- 具备实际原始图文件的事件数。
- 具备完整七维反馈且满足本次关联条件的观测数。
- 反馈缺失/过期和源图缺失，不掩盖为完整输入。

当前 state 为六实测关节rad + 实测夹爪总开口m；未来 action 为六绝对关节目标rad + 绝对开口m。训练关节delta相对动作块起点，服务返回已恢复绝对目标，执行端不再累加。

读取现有URDF/FK与SDK定义，登记基座、法兰/工具帧、关节顺序、符号和零位的证据。未物理确认的项继续标未确认；不靠一张静止图把六轴映射全部判为通过。

### D. 单相机 π0 / π0.5 接口与全参配置

新增模块保持历史仿真模块原样。训练和推理使用同一个单相机转换。

| 项目 | π0 | π0.5 |

| 唯一真实RGB | 相同 camera_rgb 与实际安装slot | 相同 |
| 状态输入 | 连续state | 离散state token，显式启用 |
| 归一化 | mean/std | q01/q99 |
| 机器人物理量 | 7维：6关节rad+开口m | 相同 |
| 模型内部action维度 | 保持预训练32维padding | 相同 |
| 全参模型结构 | 非LoRA gemma_2b/gemma_300m，全部可训练 | 对应π0.5结构，全部可训练 |
| 基础权重/资产/输出 | π0独立目录 | π0.5独立目录 |

### 安装方式决定手眼采集关系

固定外部相机：相机固定于机器人外部；板刚性固定在末端固定构件，随末端移动。若没有这种刚性安装或独立测得的板/基座关系，不用错误姿态关系强行求解。

令 G_i=T_base_gripper，C_i=T_camera_board，求 X=T_base_camera，则：

~~~
inverse(G_i) * X * C_i = T_gripper_board（固定）
~~~

腕部相机：相机固定在末端，板固定于基座/桌面且机器人基座不动，求 X=T_gripper_camera：

~~~
G_i * X * C_i = T_base_board（固定）
~~~

所有 T_A_B 都表示将B系点变换到A系；平移单位m。独立姿态应验证上式固定量的一致性，不能仅凭训练图的重投影误差低就宣布手眼通过。
[OpenCV官方手眼定义](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)。

手眼标定不会自动解决RGB–depth配准；当前B/新π接口以RGB为输入，原始深度保留诊断。
