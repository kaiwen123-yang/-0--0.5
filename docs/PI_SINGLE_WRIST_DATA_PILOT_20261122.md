# Piper H 单腕真实数据采集与 RoboMIND 2.0 适配

2026-11-22 在第二开发平台完成本机短段实采、历史指令关联和公开样本检查。本机已有记录能关联 RGB、六关节、夹爪及当时的目标。公开数据中找到以右臂运动为主的一条关冰箱门样本，已导出 2,243 行原始数值和 3 张原始右腕 JPEG。两项均用于检验数据结构；本轮新的成功抓放示范数为 0。

## 本机抓放示范怎么采

**第一条建议任务是把一个轻质方块从固定起点放入浅盘。** 指令、取物区、放置区和成功条件先记入本次 episode。开始时双方能够从腕图定位物体和放置区域，支架与标定时一致。现场完成一次抓取、抬起、放入及释放，保留真正执行的指令、测量和结果。若掉落、遮挡或途中停止，给这条轨迹写清失败阶段和原因。同一任务后续再改变起点或放置位置，并按整条 episode 划分训练和留出。

从 11 月 16 日 H0 夹爪开合和小幅 J6 运动留下的 6 张真实 RGB PNG 重做了关联。6/6 能读到六关节及夹爪状态。3/6 图像到达时，已有完整的关节和夹爪目标，且与 SDK 钩子记录的 0x155–0x157、0x159 报文字段相符。最早三张此前没有明确下发的夹爪目标。旧钩子记录的是 SDK 交给发送层的字节，没有逐帧总线送达确认；三个完整向量表示该时刻最近的已记录设定值。该会话只覆盖台架动作。此前 5,382 张腕图所在的 180 s 静止会话仍仅用于观测。[六条实际关联](../results/robomind-research/20261122/local_alignment.json)

这六张图的主机接收时刻比 ROS header 晚 248.4–332.3 ms，约为 5–7 个 20 Hz 周期；最近关节反馈距图像**接收**时刻只有 0.94–5.11 ms。两项数字来自不同的时间差。第一条正式抓放要连续核对帧号、来源时刻、主机接收延迟、实际发送时刻和追踪反馈，特别是夹爪闭合前后。旧会话不能只靠“接收时距关节很近”就填成完整策略监督。一次停稳标定能够解决成像几何，连续抓放仍要测量运动中的时序。

### 进入训练前尚缺的三个定义

1. **时间基准。** 五个样本的相机 timestamp 均是类似 Unix 秒的整数，实际相邻差值只有 0 或 1。关门样本 2,243 行中有 2,220 对相邻行时间戳相等。这能验证数据在行上的对齐，无法仅凭这些值重建毫秒级采样时间或凭空补出严格 20 Hz 网格。需核对该批采集器记录频率、对齐/重复帧规则或原始高精度时间。
2. **夹爪映射。** 牛奶样本左从臂数值约 −0.00105～0.06342，石榴样本约 0.03948～5.42592。关门样本右侧主臂夹爪全程 −0.00728，不能用它确定夹爪比例和零点。应从源端采集代码或已知张开距离取得该批的单位、符号和“总开口”定义，保留原值。
3. **关节与动作语义。** 主臂参考与从臂实测有追踪差异。仍要核实源 Piper 具体型号、轴序、方向和机械零位，以及主臂到从臂实际下发命令的映射。若直接照本机轴序和 rad 解释关门样本右臂参考，有 **849/2,243 行**至少违反 J2 或 J3 的本机零端边界。直接裁剪会改写示范动作。关门右臂夹爪基本不变，这一条也不能单独教会抓取和释放。

因此，本轮可复用的是读取器、经检查的相机键、逐侧数值和筛选方法。公开数据可以继续用作适配候选；只有语义、时序和任务独立性落实的训练 split 才用于本机策略监督、π0 的均值/标准差和 π0.5 的分位数统计。尚未启动训练或实机策略推理。
