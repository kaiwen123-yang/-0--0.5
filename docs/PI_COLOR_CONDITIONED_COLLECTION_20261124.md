## 1. 目标及适用范围

采集全库覆盖蓝、红、白、绿四种目标。阶段A仅用真实指定目标为蓝/红的合格episode训练π0和π0.5，白/绿目标episode完整保留，供以后四颜色适配。

第一阶段目标：**在红蓝同时摆放、固定托盘、同一腕部安装、已明确的可见可达桌面区域内，输入蓝色或红色指令，机器人依据当前观测选择对应目标并完成抓放。** 用户最关心蓝块位于不同位置时仍能抓对，红目标示范和对照用于避免模型忽略语言、始终只抓蓝。

“任意位置”在首版限定为该可见、可达区域内的新位置和轻微朝向变化。它不包括画外、机械臂不可达、训练未覆盖的远距离、高度改变、堆叠或重遮挡。训练结束不等于该能力通过；后续用未参与训练/选模型的新布局验证，不能在训练前承诺一次训成或所有连续位置绝不失败。

## 2. 先修真实指令到导出的链路

固定基准的 [demo_export.py](https://github.com/kaiwen123-yang/-0--0.5/blob/b6e3f34c2b8c9cf5e46ca01c10e7224506408d51/tasks/piper_real_single_v1/demo_export.py) 仍有全局常量：

```python
PROMPT = "Pick up the block, place it in the shallow tray, release it, and retreat."
```

每个index条目都写 `prompt=PROMPT`，会丢失颜色。当前公开teach只有会话/placement，没有逐条颜色参数。现场若已修改，先核对实际代码和导出结果，避免重复实现；不能提供尚不存在的 `--prompt` 或颜色筛选命令。

模型侧通路已有：`dataset.py`读取entry.prompt，`policy_config.py`传入模型，`infer.py`读取观测NPZ的prompt。本轮所需是将**任务选择→源示教/运行→审核→index.prompt→推理**贯通，不更换模型架构。

每条运行至少保留以下真实信息，字段名是本次拟定接口、尚待落实到现有代码：

| 字段 | 定义 |
|---|---|
| run_id、source_trajectory_id、session_id、placement | 既有真实运行、路径来源、会话、布局，不重造ID |
| target_color | **指令指定的目标**，blue/red/white/green |
| scene_colors | 本次实际摆放的任务方块颜色，不是画面所有背景颜色；与指定目标分开 |
| prompt | 本条完整指令，一条episode一个目标 |
| destination_id | 本批固定浅盘的标识及布局参考 |
| actual_grasped_color、结果 | 实际抓了什么、抓放是否成功、是否介入；无法判断则据实记未知 |

蓝指令却抓红，应按原指令记录失败，不能改target_color为red凑成功样本。旧资料可按原图/视频与现场记录补可核实标签，保留补注来源和原始版本；不根据颜色出现就推断操作者意图，不复制同一动作改成四种颜色标签。

四条推荐规范指令：

```text
Pick up the blue block, place it in the shallow tray, release it, and retreat.
Pick up the red block, place it in the shallow tray, release it, and retreat.
Pick up the white block, place it in the shallow tray, release it, and retreat.
Pick up the green block, place it in the shallow tray, release it, and retreat.
```

中文入口可以将“抓取蓝色方块到托盘里”等受支持表达明确映射到对应固定指令。这是接口功能，尚待实现，不等于已证明模型理解任意中文。若直接用中文训练/推理，也要保持逐条真实标签和单独验证。阶段A界面明确只开放蓝/红执行；白绿数据已采不等于阶段A已学会白绿。

## 3. 四颜色怎样采：同时包含两种场景

**场景A：只有蓝、红各一块。** 这是第一阶段最重要的部署分布，需要足够直接示范。

**场景B：蓝、红、白、绿各一块。** 分别指定四种颜色，每次只抓指定的一块，其他物体保留作为干扰。蓝/红目标的这些episode仍可用于阶段A；白/绿目标的episode留给以后。阶段A若看见白绿干扰物，后续不能把白绿描述成从未见过的颜色；只是白绿目标动作未参与本阶段训练。初版每色只放一块，避免“抓蓝”对应多个蓝块的歧义。

优先使用同尺寸、同形状、接近材质的哑光方块，保持光照稳定，白块与桌面应能区分。保持托盘、底座、腕相机安装及received图像处理链不变。四块和关键接近区域应在当前腕图中可辨认；如果某些位置看不见，先调整物体布局到现有视野内，不假定模型能抓画外目标，不因本计划要求新增相机。

### 必须有的真实对照

| 操作 | 作用 |
|---|---|
| 同一红蓝布局，抓蓝；复原后抓红 | 相近视觉/同一公共起点下，指令变化对应真实不同目标 |
| 蓝红交换位置后，各抓一次 | 避免蓝等于左、红等于右的位置捷径 |
| 四色布局分别指定四个颜色，每次真实复原 | 保留四颜色任务的完整真实监督 |
| 不同布局中轮换每种颜色的位置、轻微朝向 | 每色均覆盖多个位置，颜色不固定绑定某个位置 |
| 保留若干新布局只用于验证/最终实机测试 | 检查新位置是否有效，不只重放采集时布局 |

在已经核查的可见可达区域，用照片/布局图明确边界，按左中右、前中后组织采样；不强行凑满不可见区域。公共机械臂起始姿态尽量一致，避免起点本身泄露目标。当前采集仍是示教路径重放，改变目标空间位置需要对应真实源路径和必要的空场核查，不能只挪方块继续运行旧A01路线。

已有单蓝或单物体记录保留，可作为相应资料；它们不能替代红蓝混摆的目标选择对照。正式资格继续遵守已选SDK宽度合同、合法源窗口、正常任务终点、独立重定位和实际成功审核。四色目标不会自动提升旧commissioning资格。

## 5. 先冻结全库split，再筛阶段A

1. 全四颜色主库保留每条真实episode、任务颜色、场景颜色、prompt、资格和来源。
2. 先按session_id、placement、source_trajectory_id冻结train/validation。现有导出器分别禁止这三者跨集合；同一布局的不同颜色对照和同源重复整体留在一组。
3. 阶段A筛选条件为：质量/训练资格通过，review确认抓对指定颜色且完整任务成功，并且 **target_color∈{blue,red}**。split继承主库，不重新随机拆分。
4. `scene_colors`不是筛选目标依据。蓝/红目标episode里可以看见白绿干扰物；白/绿目标episode即使蓝红在画面中，也不能算蓝红监督。
5. 阶段A不裁掉白绿像素、不改原始动作、不把白绿目标重标为蓝红。主库及旧导出保留，派生视图可用独立dataset/index/alignment清单引用主库既有数组，避免重复复制大型RGB NPY。现有reader按root/entry.directory读取，需保持来源链接、路径和元数据对应。
6. 两模型训练spec都指向同一阶段A视图；π0/π0.5分别只用**阶段A的train**计算自己的norm。不能先按四色全库或含验证数据算norm再筛。

当前导出器没有上述颜色筛选接口，需在现有模块小范围实现并实际核对新记录，不另建通用数据框架。蓝/红的reader输出必须保留各自prompt，不能被全局常量覆盖。

## 6. 部署必须由模型根据当前观测选择动作

正式训练完成后，用实际检查点、同一腕图像链、实时关节/夹爪和本次指令做推理；接入经过验收的唯一现场发送端，记录实际模型输出与实际提交。现有保存NPZ的infer入口仍是只读，不能把训练结束或旧SDK轨迹重放说成在线自主选色已经实现。

第一阶段先在红蓝混摆的新位置测试，不沿用人工预先选定目标轨迹代替策略。输入蓝/红命令切换后，系统需要在相同公共起始条件下选择不同目标；推理后的在线动作调度、时延与保持逻辑沿既有计划验收，不新增竞争CAN发送进程。

### 初步验收建议

每模型先做20次独立任务：10次蓝、10次红，在至少5组未参与训练/选模型的新红蓝布局上，包含位置交换并交错目标指令。任务前真实复原布局，保持固定目的地。

- **目标选择：建议20/20选对指定颜色。** 没有明确选择或无法判定不能算通过。
- **完整任务：建议至少18/20成功，其中蓝至少9/10。** 成功须抓对目标、抓起、放入固定浅盘、释放后留盘、空爪抬离、无人救场。
- 分开记录选错颜色、接近偏差、抓空/滑脱、放置失败、不可见目标、干预和控制中止。没达到就按实际失败补数据/修对应环节，不宣称已经满足目标。

这些数字是项目首轮验收建议，并非统计保证或“任意位置零失败”的证明；20次仍是小样本，区域之外能力未知。蓝/红都必须测试，否则“永远抓蓝”的策略也可能在只问蓝时看似成功。以后若用该测试集选模型，它就不再是独立最终测试。

Physical Intelligence的[知识隔离研究](https://www.pi.website/research/knowledge_insulation)明确讨论连续动作VLA忽略语言的现象，并分别评估语言服从与任务表现。因此本项目也分别统计选色和完整任务，不仅看训练loss或单次漂亮演示。
