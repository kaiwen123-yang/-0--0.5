# DC1 RGB 畸变参数差异：源码核对

日期：2026-11-20。范围：解释 H0 已保存的 CameraInfo D=0 与设备 r_k 非零。没有修改驱动、设备参数或现有标定文件，没有生成新的标定结果。

## 直接读到的证据

H0 配置记录驱动为 orbbec/ros2_astra_camera@f7e71d9ce806e788cb48d8580aac2c778fba4214。对应源码：

[ob_camera_info.cpp](https://github.com/orbbec/ros2_astra_camera/blob/f7e71d9ce806e788cb48d8580aac2c778fba4214/astra_camera/src/ob_camera_info.cpp)

- OBCameraParamsToCameraInfo() 将 SDK 参数重排成 ROS/OpenCV plumb_bob 顺序。
- getColorCameraInfo() 的有效设备参数分支先生成 default_camera_info，再新建 camera_info，将 D 初始化成5个零；随后复制 K/R/P，没有把中间对象的 D 复制过去。
- 因而这条源码路径能够产生“服务参数非零、发布 D 为零”的现象。现场应确认当前仍使用该分支、同一版本及相同图像设置。

映射关系：

~~~
ROS/OpenCV D = [r_k[0], r_k[1], r_k[3], r_k[4], r_k[2]]
顺序 = [k1, k2, p1, p2, k3]
~~~

H0 [设备服务原记录](https://github.com/kaiwen123-yang/dog-and-arm/blob/284c1f3f1bb9d5096003433f6153a9c5e95d6189/results/hardware/h0/20261116_2051/logs/camera_services.txt) 中：

~~~
r_k = [0.0749608, -0.09909887, -0.00020435, -0.00035161, 0]
~~~

按上述驱动代码重排的候选值为：

~~~
D_candidate = [0.0749608, -0.09909887, -0.00035161, 0, -0.00020435]
~~~

这是已有服务参数的确定性重排，**不是经棋盘验证的新标定**。精度来自原日志的显示位数，不补造更多有效数字。

## 当前能下什么结论

可以确认源码中存在不复制 D 的行为，可以保留这一解释作为现场审计依据，也可以明确 r_k 不能原顺序直接拷贝进 OpenCV。

不能仅凭这一段源码排除设备内部图像处理，也不能据此断言当前收到的每一幅图都应该套 D_candidate。当前话题名 image_raw 与 D0 本身均不足以证明原始/校正几何。
