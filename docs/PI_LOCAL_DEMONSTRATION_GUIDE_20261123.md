### 2.2　待实现：正常在放置后抬离处结束

新源的任务窗口应为开始→接近→闭合→搬运→释放→抬离，在真实抬离姿态静止后正常 E，元数据明确为 `post_release_retreat`。这需要同步修改录制、路径检查、重放及导出对终点的定义，保留逐样本限位、连续性、静止标记和真实来源；不能通过修改旧 A01 的 `selected_retreat`、资格字段或放松异常检查来实现。

**仅修改 E 还不够。** 新源第一次示教结束时手臂位于抬离姿态，尚未有这条源的真实空场轨迹。退出示教后的模式交接、当前实测姿态与保持目标的建立、首次返回起点，必须另行实现并在现场验收，随后才能开始该源第一次空场。现有 `return-start` 依赖已执行同源空场，不能解决这个首次返回问题，也不能借用其他路径的空场记录充当本源依据。默认最小方案为：E 先封存任务 end；仍在被动示教模式下完成单独人工重定位，保存为 reposition_only 且不改变任务窗口；在已验证的健康近起点范围退出示教，再用新反馈接续已有近零模式交接与同位锚定。此阶段和新合同需要有针对性支持，不能直接套当前 commissioning 的 restart-teach，也不默认实现任意远位自动回零。该流程完成前不提供假定可用的新命令；实现任务见[下一轮提示词](PI_A01_NEXT_PROMPT_20261123.md)。

## 3　移走方块，走一遍真实空场路线

以下是现有 `empty` / `review` 的行为，前提为本源已正常建立、当前已处于有效起点且模式交接完成。新 `post_release_retreat` 源先完成第 2.2 节的首次返回验收。已有 A01 的同一路线和布局已通过空场，无需为了续采重复本节。

只移走方块，固定盘子、支架和线缆。人退出动作区，能观察整条路径与现场急停。运行两条独立命令：

```bash
bash "$D" empty "$S"
bash "$D" review "$S"
```

执行前会显示规划用时。程序先检查先前实际提交的保持位、本次 boot 与主机 TX 变化；在需要切换时，复用 H0 近零灯灭→待机→CAN 的确认流程。保持位、实测姿态或控制器反馈不相符时停止。MOVE_J 档位 5%，参考速度最多 2.5°/s，逐段参考加速度上限 8°/s²，名义目标间隔 50 ms。每段沿真实路径运行；夹爪标记处先确认关节到位再发开合。普通轨迹点连续下发。

**在一段确实缓慢移动、离开桌面和盘沿的路径上，试一次 P 回车。** 等“暂停，保持已确认”，观察无继续推进或下沉，然后 **R 回车**继续。空场审核要求暂停前 0.4 秒的实测位移大于 0.1° 且已成功恢复。E 回车请求提前结束并确认当前目标保持，整条记为中断。P/E 在路径调度处受理，不能用作即时急停。遇到危险按现场物理急停。动作故障或运动时 Ctrl+C 走阻尼急停路径，机械臂可能下沉；软件提交急停也要现场确认。正常结束由程序确认到位并保持，全程不以失能作为正常收尾。

`review` 自动选该会话最近的空场/实物执行，打印质量统计、打开完整腕图回放和 `trajectory.png`。可指定终端打印过的绝对执行目录复核某一条。看盘沿净空、线缆、抓取与释放时机、实际开口和最终保持；逐通道检查目标与实测。全部符合再输入 **PASS**。未通过时输入问题和阶段，保留该次记录；若实质修改路线，重新 `teach` 并重做空场。相机图未必能拍到臂后侧，现场目视和录像都要看。

选用独立抬离终点时，空场到位或一次同源实物执行正常结束后，先移走方块及工具，保留盘和胶带，确认回程净空。可在该会话运行 `bash "$D" return-start "$S"`。程序核对已通过数值核查的真实空场记录、当前锁存目标与关节反馈，并将空场已经实际提交的关节目标倒序下发。回程会经过空盘和原抓取位置，夹爪始终保持张开。长时间相同的量化目标仅保留首尾各五步，其余不同目标全部保留，参考间隔为 50 ms。此独立返回不计入示范；程序到位保持后再摆放下一条的方块。

## 4　摆回方块，一次只做一条

对已有 A01，先按第 0 节返回并核对起点，再把方块放回 A01 的原位置、朝向。每条开始前确认盘子未移、夹爪张开、没有人手在轨迹内。下面两条命令运行一次、复核一次。首批 3–5 条用于检查完整链路与示范质量，可以由改进后的紧凑新源贡献，不要求先重复旧 6 分多钟轨迹达到数量。

```bash
bash "$D" block "$S"
bash "$D" review "$S"
```

要亲眼看到夹起、搬运、放入盘、张开后物体留盘、空爪抬离，全程无人工救场，才能输入 PASS。抓住物体时 SDK 开口反馈可大于闭合目标，两者都保留原值；该反馈不等同于卡尺测得的指垫净距。滑脱、未进盘、碰撞、暂停或人工帮忙，都保留原始执行。已知失败可直接记录现场原因，例如：

```bash
bash "$D" review "$S" --failed '转移时滑脱，未入盘'
```

每次审核后先确认实际终态；结束在抬离处时按第 0 节独立返回后再摆物体，不要循环无人值守启动。换方块位置/朝向时使用新布局编号和对应源示教，重新核查该源空场。现行 `teach` 可更新会话内源，但整会话必须归于同一数据 split；正式阶段建议用第 6 节的独立会话安排。本次保持来源若已失效，先读 `status` 并查原因；旧入口只在已确认的近零、已使能 CAN/MOVE_J 起点新开会话，不能把它当作从当前抬离姿态自动复位的命令。

## 5　核对动作来源并导出

```bash
bash "$D" export "${S}_commissioning" --commissioning "$S"
```

默认实物样本为 `commissioning_only`。联调导出采用 `commissioning` split，现有 reader 可按该 split 读取。正式训练入口要求独立的 `train` 记录。失败、部分下发、手拖和空场均无法进入成功导出。已有输出目录会保留，再次导出选新目录。

| 文件 | 现场复核内容 |
| --- | --- |
| 每次执行的 `run.json`、`feedback.csv` | 同机 boot_id、来源与终态；每个 0x2A5–2A7 完整有序组、0x2A8 独立反馈、接收时间、原始字节和有符号值 |
| `tx.csv`、`commands.jsonl` | 真实 send_bus.send 开始/结束、CAN ID、字节和返回/异常；请求值、源轨迹节点与插值进度、实际提交并从字节解码的目标、部分提交。主机提交和到位反馈分开 |
| `rgb/`、`rgb.csv`、`rgb_status.json` | 全部 received RGB 原图、ROS header、回调时间与写盘/队列计数。header 表示驱动时间；未经独立曝光同步验证 |
| `review.json`、`quality.json`、`trajectory.png` | 实物结果、反馈/图像年龄、三报文跨度、收图和动作间隔、提交次数、动态误差、开合和保持终态；失败的运行保留可取得的原始证据 |
| 导出的 `dataset.json`、`index.json`、`alignment_manifest.json`、每条的 `row_sources.jsonl` | 每步指回源图像、实测反馈、当前保持与未来目标的 ID、时间、年龄和有效区间 |
| 每条 episode 的四个 NPY | `state.npy`、`actions.npy`、`camera_rgb.npy`、`policy_timestamps_ns.npy`；直接供现有 `SingleCameraDataset` 读取 |

对严格 50 ms 网格起点 t，使用 t 时已收到的最后一张图、最后一组完整六轴和最后一次夹爪反馈。行标签取 (t, t+50 ms] 末端最近一次可确定的完整保持目标；边界落在三包提交过程时，退到该提交之前的最近一致时刻并记录偏移。两类目标各自持有，未发新命令的轴/夹爪使用先前真实提交的来源。保留 t 时的当前目标用于核对动态误差。10 步 chunk 由 reader 拼本 episode 的相邻行，末尾重复该 episode 最后一行。每次真实导出会通过当前 reader 核对末行行为。

`state` 来自真实接收反馈，`action` 来自真实提交目标和提交时间；不能复制实测反馈冒充动作标签。夹爪反馈 24.7 mm、闭合目标 15 mm 在带物时的差异具有实际意义，不能为让两列接近而覆盖其中一列。

## 6　正式采集计划：完成代码与现场验收后启用

**目前 A01 的正式执行仍为 blocked。** `block --formal` 的参数已存在，但 `prepare-pads` 的 `commissioning_only` 配置和 `selected_retreat` 各有独立拒绝条件；现在不能对 A01 使用该参数，也不能仅靠改文档、凑够 3–5 条或编辑 JSON 解除限制。

下一轮计划实现并贯穿准备、录制、执行和导出的版本化契约 `piper_h_sdk_width_m_v1`：模型第七维 state 为设备实际反馈的 SDK 宽度（m），第七维 action 为真实提交的 SDK 宽度目标（m），卡尺指垫净距作为独立物理核查记录。这个名字不表示完成全程指垫净距标定；不做未经验证的统一偏置换算，也不把实测反馈复制成目标。正常 `post_release_retreat`、首次模式交接/返回及对应导出资格同样要实现、实际验收并留证。当前历史 A01 继续作为 commissioning 保留，新契约的代码与现场入口完成前，不发布新的正式运行命令。

满足上述条件后，目标为约 30–50 条有差异的完整成功执行。先在当前已验证且看得清的区域改变方块位置、轻微朝向及落点，为不同布局示教、核空场，再逐条实物执行与审核；重复同一源/同一布局不替代有效多样性。首批紧凑源避免教学时的长等待，仍保留必要的静止标记与实际执行中的合理保持。

正式导出已有 `export 输出目录 --train 训练会话目录… --validation 验证会话目录…` 形式，但只能接收资格通过的新正式记录。同源轨迹、同一真实布局 ID 或同一会话不得跨 split。建议在采集前就分配独立会话，例如：

| 计划会话 | 用途 | 布局与源示教要求 |
| --- | --- | --- |
| T01 | train | 训练布局组 1，独立会话及该布局实际源路径 |
| T02 | train | 训练布局组 2，独立会话及不同布局实际源路径 |
| V01 | validation | 留出的验证布局组，独立会话，不能复制 T01/T02 源或仅改布局名字 |

T01/T02/V01 是规划编号，不是已存在的现场目录；实际目录与分组要记入清单。50 条可从 40 train / 10 validation 起步，按整组分配而非逐帧随机切分，数量不是效果保证。两个模型共享冻结分组，各自使用实际 wrist 全参配置和 train-only 统计；π0 使用 mean/std，π0.5 使用 quantile。正式数据、训练预算和 GPU 状态齐备后再训练。
