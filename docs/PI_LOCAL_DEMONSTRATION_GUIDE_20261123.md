# Piper H 单臂本地训练示范采集指南 · 2026-11-23

状态：依据 π 仓库 main@72ad763699502defed9d39d51bd22a56ea2ce2e8、现场 pyAgxArm@d90e234ba8e408cfa964b38aa9120b3131fc9f85、Piper H 官方手册与官方轨迹录放示例只读审查。此文规定应实现和现场完成的流程；本轮没有机器人动作，也没有声称新增采集命令已经可运行。

## 1. 采用什么方法

本轮已按用户要求先检查 RoboMIND：有值得保留的单臂子任务，但没有确认可直接满足本机任务、关节/夹爪映射和单腕观察条件的正式批次。依据 [本次数据决策](ROBOMIND_DECISION_20261123.md)，下一轮主线采本地训练示范，不需要再购买 UArm、第二条机械臂、VR 或选配示教器。

本地方法是：

1. 人用现有 Piper H 拖动示教功能，记录关节路径；在抓取、放置位置标记夹爪“合”和“开”的意图。
2. 退出拖动模式，沿当前已验证的待机→CAN 路径交还唯一 SDK 发送端。
3. 先空场低速走通这条真实路径，再摆上物体执行。
4. 在机械臂自己完成抓取、搬运、释放时，保存腕图、真实下发目标与真实反馈。
5. 用通过质量审查的成功执行数据训练 π0 / π0.5。

人的手拖路径是“轨迹来源”。训练用的是后面的真实机器人执行。不能把手拖时读到的关节位置直接复制成 action；也不能把失败的抓取、被人帮忙放进盘中的结果标成自主成功。

## 2. 哪些按钮和命令现在已有，哪些要先开发

| 能力 | 当前证据 | 使用边界 |
|---|---|---|
| 机械臂实体按钮单击开始/结束拖动记录 | Piper H 手册 §3.1 | 已有，绿灯常亮为录制、灯灭为结束 |
| 实体按钮双击重放控制器内部轨迹 | 手册 §3.1 | 已有，但内部回放是否向主机输出完整目标未证实，不用它作为默认训练标签来源 |
| pyAgxArm 读取六关节、机械臂状态、夹爪反馈 | 固定版本 driver 源码 | 已有，仍需检查反馈新鲜度和来源 |
| pyAgxArm move_j 与 move_gripper_m | 固定版本 driver 源码 | 已有底层 API；不是完整示范采集 CLI |
| 现有腕图与 CAN 反馈记录 | π 仓库 RECORDING_USAGE.md 和现场报告 | 已有真实入口，仍须和动作日志关联 |
| 键盘标记 CLOSE/OPEN、开始/结束一条示范 | 当前任务目录未提供完整入口 | 需要 Codex 实现一个小模块 |
| 带真实发送结果、图像和反馈的路径重放与 episode 导出 | 当前任务目录未提供完整入口 | 需要 Codex 实现，复用既有 SDK、锁和采集链 |
| 正常“暂停并保持”、继续、结束后的明确状态报告 | 有已验证静止 hold 与有限条件超时保持，但没有完整动态任务接口证明 | 必须在新模块中接好并做当前轨迹实测，不能把 kill 或 Ctrl+C 当正常停稳 |

官方 Agilex-College 的 recordTrajectory_new.py 和 playTrajectory_new.py 确实存在，但使用另一套 piper_sdk 接口，播放示例默认速度百分比 100，并带旧式急停恢复流程。它们提供方法依据，不能作为这台已完成联调的 Piper H 的直接操作命令。不要为运行示例卸载、替换现有 pyAgxArm 或修改共享 SDK/H0。

下文建议的 Enter、C、O、E、Space 等软件键属于待实现界面约定；只有 Codex 完成模块并给出其实际 --help 与绝对路径后，才是可执行操作。当前可复制给现场 Codex 的任务在 [下一轮执行提示词](PI_POST_CALIBRATION_NEXT_PROMPT_20261123.md)；它应先把缺失入口做成真正可操作的界面，再带用户采集。

## 3. 第一项任务与现场布置

先做一个明确的小任务：“把桌面上的一个轻质方块放进固定浅盘，然后退回”。

选尺寸小于现场已验证最大张开量的轻质哑光方块，2–3 cm 方块可作为候选，但以实际指尖空间、已测开口和可夹持性为准。浅盘要稳定，入口宽松。第一批先固定盘子的位置，只改变方块在已验证小区域内的位置与少量朝向，减少同时变化的因素。

固定腕部 DC1、线缆与基座，继续使用本次标定绑定的安装。示范开始时，腕图须能看见方块及其邻近桌面；接近、抓取与关键转移阶段要检查画面是否足以判断任务。单腕相机不保证任何姿态都能同时看到方块和盘子，因此先选现场画面真正覆盖得住的布局。不要为了采集临时改变相机支架后仍沿用旧标定。

给每个摆放方案拍一张起始参考图，记 placement_id、相机/标定版本、轨迹编号、任务指令和日期。初始姿态来自现场实际取得的可达姿态，不能拷贝历史日志中的绝对关节角作为盲发目标。

## 4. 手拖示教：夹爪不必在手拖过程中真的夹物

### 4.1 开始前

启动或复用现有相机驱动与被动记录器，避免第二个相机驱动和第二个主动发送进程。新轨迹记录模块读现有真实反馈事件，并记录来源、单调时间和 boot_id；它不能靠 viewer 中每两秒才刷盘的 CSV 做实时状态。

夹爪先处于已经验证的张开状态。第一次正式采集前，用几个实际开口核对反馈方向、总开口单位和闭合零点；11/22 闭合附近曾读到 −0.0001 m，原值要保留，不能静默截成 0 或把单位猜成毫米。确认换算后将原始值与统一 m 值同时留存。普通夹爪和选配示教器不是同一件东西；不要强掰已使能的夹指，也不要把夹爪零位标定、失能、重新置零当成每条示范的操作步骤。

### 4.2 按实体按钮并记录路径

确认灯灭，单击实体按钮；现场确认灯常亮、反馈处于示教状态后，才在新模块按 Enter 开始记录。程序应保留起始静止段、全部有时间戳的关节反馈与末尾静止段，不能只保存位置变化的稀疏点。

人沿以下顺序轻缓拖动机械臂：

| 阶段 | 人的操作 | 夹爪标记 |
|---|---|---|
| 起始 | 移到本次真实确认的起始位置 | 维持已知 OPEN |
| 接近 | 移到方块上方，再沿可检查的路径下降 | 无 |
| 抓取位置 | 开着的两夹指对准并包围预定夹持区域；短暂停住 | 按 C，记录 CLOSE 意图，不在示教状态发送夹爪动作 |
| 提起 | 按预定安全路径提升到可越过桌面和盘沿的高度 | 保留 CLOSE 意图 |
| 转移 | 移到盘子上方，再到释放位置 | 无 |
| 释放位置 | 短暂停住 | 按 O，记录 OPEN 意图 |
| 退回 | 抬起、移开，回到可保持的结束位置 | 保留 OPEN 意图 |

这一次夹爪可全程保持张开，物体也可以留在桌面原位。我们记录的是抓放路径和开合事件，真正抓起物体发生在后续机器人重放中。手和遮挡进入这一遍图像不构成训练视觉输入，因为这遍不作为成功执行 episode。

若连续拖动不方便，可以分为“接近到抓取”“提起到释放”“退回”三段分别记录，或保存足够密的真实路径点。每段边界必须明确，接续路径需要检查，不能只连几个端点就假定关节空间插值不会扫过桌面。主机保存的多段路径不能依赖控制器内存：手册说明每次新记录会覆盖前一段内置记录。

### 4.3 正常结束录制

在新模块结束路径记录，再单击实体按钮，确认灯灭。软件停止写文件不等于机械臂退出示教。随后由当前已验证流程执行待机→CAN，并核对反馈模式、六轴使能、故障状态与当前目标来源。

Piper H 手册 §3.1 的相关原文是：“发送控制模式为待机模式，再发送控制模式为can控制模式。” 内置记录最长三分钟；新录覆盖旧录。这些事实应写进操作界面，避免误双击触发内部重放。

不要运行旧教程中无条件急停再恢复、等待零位、自动失能的切换代码。当前 cf01b43 已修复的普通到位超时保持，只在健康、反馈新鲜、近目标且静止等窄条件成立时有效；它没有证明运动途中任意暂停都可以按同样方式处理。

## 5. 先走通真实空场路径，再放物体录成功执行

### 5.1 一条新路径第一次重放

Codex 先检查这条真实路径的关节范围、路径连续性、步长、速度与加速度预算、夹爪事件顺序和工作区间隙。原标定程序的单次 2° 小动作范围不自动覆盖整段抓放路径；新任务需要显式审查完整路径，不能取消已有边界来让程序通过。

先拿走待抓方块，保留固定浅盘及其他实际场景布局，按实际示教的起始条件，以当前已验证的低速行为执行一遍真实空场路径，夹爪也按标记做一次真实开合。这次检查目标是确认路径、相机线缆、夹爪时机、记录链和正常暂停/保持；它是现实中的任务路径检查，不是合成训练示范或模型容量试跑。

新发送器应复用唯一发送端锁和 MOVE_J 路径。不要因追求响应快而切换到 move_js；官方源码把它列为没有平滑/规划的立即响应模式，需另行验证。不要每个动作调用一次标定脚本，也不要把每次 0.5 秒静止到位等待插进连续轨迹的每一帧。

### 5.2 摆回物体并执行

空场路径通过后，把物体放回该轨迹对应的摆放位置，确认人的手退出运行路径，启动一条真实 episode：

1. 先记录真实起始腕图、关节/夹爪反馈与已知保持目标。
2. 机械臂自己接近抓取位置。
3. 到达抓取标记时保持关节目标，发送实际夹爪闭合命令并记录目标开口、力参数和反馈。
4. 按经现场确认的夹持等待条件继续提起与转移；夹住物体时实际开口不必等于零，不能因“没有到达完全闭合目标”误判正常夹持失败。
5. 到达释放标记时保持关节目标，发送真实张开命令，记录开口变化与物体释放。
6. 完成退回并正常保持，记录结果和结束后的实际模式/使能状态。

夹爪目标开口与力度采用现场已经验证、适合这个物体的值，不把官方示例的任意数值直接当推荐值。C/O 标记只是源轨迹事件；真正 action 来自这一遍真实发送的指令。

运行期间不要有人帮它夹住方块、搬动盘子或把方块放进去。失败和人工介入都保存记录并标明原因，初期成功模仿训练不混入这些记录。

### 5.3 暂停和结束

正常暂停必须停止推进后续参考目标，并通过新模块接入的已验证保持路径处理；继续时重新核对姿态、目标和反馈。程序需要单独实现并验证这个行为。不能把 Space、结束按钮或自动时限简单映射成 Ctrl+C、kill、驱动失能或阻尼急停。

紧急故障仍使用现场已有的故障处置。报告必须区分“暂停保持”“到位超时停任务”“故障急停”和“进程意外退出”，并记录最后已提交的目标与实际机械臂状态。尤其不能把 cf01b43 的静止超时条件扩展描述成动态通用安全停机。

## 6. 训练数据究竟保存什么

最低要求是在同一台主机、同一次 boot 的时间基准上，可以从任何一帧找到其图像、此前的真实测量、实际目标以及发送结果：

| 类型 | 关键内容 |
|---|---|
| 原始视觉 | 完整未叠字腕部 RGB、原始图索引、ROS header、接收单调时间、camera ID、安装及标定版本 |
| 测量 state | 六关节 rad、夹爪实测总开口 m，各自反馈 ID/接收时间/年龄，三条关节报文的时间跨度 |
| 真实 action | 实际六关节绝对目标 rad、夹爪绝对总开口目标 m；请求值、限幅/插值/量化后值分别留存 |
| 发送证据 | 每条 CAN 帧 ID、字节、发送开始/结束、返回/异常、完整或部分提交；arm 与 gripper 各自保持目标的来源 ID |
| 轨迹来源 | 人工示教原路径、标记位置、路径版本、episode ID、placement/session ID、source_kind |
| 任务结果 | 实际抓起、移到盘内、释放后停留、退回，是否人工介入，失败/停止原因，完整视频与质量判定 |

SDK 上层函数返回不自动等于机器人已经执行成功。实际发送日志应拦在 send_bus.send 这一层，同时覆盖关节与夹爪；不能沿用旧 gripper 分支只在发送前打“准备发”记录。多条关节帧和单独的夹爪帧可能部分提交，要明确表示，不能写成一条成功 7D action。

动作和测量严格分列。机器人夹住方块时，闭合目标可以小于实际开口；这正说明 state 和 action 不能互相替代。夹爪某一时刻没有新命令，可以使用此前真实已提交、来源明确的保持目标，但不能把当时的夹爪反馈填成新的动作。

数据整理用 20 Hz、50 ms 网格，是数据时间分辨率，不代表模型推理已达 20 Hz。保留原始高频日志再生成网格，报告图像接收年龄、动态反馈延迟、目标发送间隔与误差。原 ROS header 尚不是已验证曝光时间，不可改名成曝光同步证据。

## 7. 先采多少，怎么避免只有一条动作反复播放

第一步先检查 3–5 条完整成功执行，默认标为 commissioning_only：从头到尾看视频，核对动作不是反馈复制、夹爪能真实抓放、事件时序正确、没有后半段漏图或错误停止。这些先作为联调检查；用户已明确接受后续本地训练示范，不需要再引入新的许可步骤。

第一批正式数据可以以 30–50 条有差异的成功完整 episode 为工程起点。这个数字是项目起步预算，不是官方最低要求，也不是全参微调一定成功的保证。

“50 条”不能理解为同一个位置同一条关节路径播放 50 次。建议在已确认可达、腕图可见的小工作区选若干不同方块位置和朝向，每个布局重新示教相应路径，真实重放并记录；固定浅盘先不变。相同源路径的重复执行放在同一数据组。换位置后继续播放原固定关节路径通常不会自动追到新物体。

一个可执行的 50 条版本是 40 条训练、10 条验证，按源示教轨迹与物体摆放/会话分组冻结。所有同源重复、相邻帧和同一 episode 不能分到训练/验证两边。具体分组数量按实际成功多样性决定，不用凑数重复来制造独立性。

另外保留新的物体摆放作为真正策略闭环评测条件。π0 与 π0.5 使用同一任务、同一数据分组和相同评测规则，再分别计算它们需要的统计量并按各自配置正式训练。若后续模型总在接近、夹持或释放阶段失败，就针对失败位置/阶段补示范；首批数量不够时用实际失败指导追加。

## 8. 给现场 Codex 的最小开发范围

仅在 π 仓库中增加一个服务本任务的小模块与实际使用说明：

- 被动记录示教路径和人工开合标记，支持完整路径及必要分段。
- 外部重放真实路径；复用当前 pyAgxArm、唯一发送锁、已验证模式切换与状态检查，不修改 dog-and-arm 或共享 SDK。
- 在实际发送层记录完整关节/夹爪目标、部分提交与反馈；与现有真实腕图记录关联。
- 给出明确的开始、标记、结束、正常暂停/保持和完成状态反馈；没有实现的行为不得显示为已支持。
- 导出可审查的完整 episode、质量摘要与日常日志条目；记录每天解决了什么、发生何种失败、证据路径、尚存问题。
- 先完成真实空场路径及 3–5 次成功实物执行审查，随后正式采集 30–50 条多样成功示范。正式示范通过质量与分组审查即可用于 train；标定/静止数据和纯手拖路径仍不直接当训练 action。

实施后必须把真正存在的命令、绝对路径和软件按键填回此指南。当前文档不应声称已经有“一键开始采示范”的 CLI。
