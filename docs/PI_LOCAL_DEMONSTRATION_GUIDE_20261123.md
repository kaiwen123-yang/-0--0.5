## 1　看腕图，选布局

在测试机桌面开三个终端。可以先在 Windows 用 `ssh dev2-ubuntu-lan` 核对状态，实体操作和图形窗口使用测试机桌面。终端 A 运行相机命令，已有单个发布者时会直接提示复用。

```bash
D=/home/kaiwen/research/pi-single-live/tasks/piper_real_single_v1/pi_demo.sh
bash "$D" camera
```

终端 B 打开实时腕图。相机用同一个 H0 环境、Domain 88 和设备序列号 CC16762023M。11/23 的现场图看得到棋盘和线缆。移走棋盘，把线缆固定在动作区外，保留腕部相机支架和底座的安装。选轻质哑光方块、盘沿低且入口宽松的浅盘。起点腕图要能辨认方块的接近区域，抓取与释放姿态都要留出指尖空间。

```bash
bash /home/kaiwen/research/pi-single-live/tasks/piper_real_single_v1/pi_demo.sh view
```

以下命令都在**终端 C 的同一个 shell** 逐条执行。设置 `S` 一次，后续各步骤沿用。每次重放自动新建带时间的执行目录。记录器仅在相应命令运行期间保存数据。原始图为无损 PNG，输出前可用 `df -h "$HOME/research"` 查看余量。

```bash
D=/home/kaiwen/research/pi-single-live/tasks/piper_real_single_v1/pi_demo.sh
S="$HOME/research/pi-q12-data/pickplace_$(date +%Y%m%d_%H%M%S)"
printf '%s\n' "$S"
bash "$D" status
bash "$D" prepare "$S"
```

`status` 只接收。读终端显示的六轴、夹爪、模式和使能，现场看机构是否静止。首批采用实测近零、健康、已使能并已到位的 CAN/MOVE_J 起点，以便复用 H0 的灯灭交接。若起点不符，保留状态和错误，先处理现场姿态。程序不会自动把手臂拉回历史零位。`prepare` 自己读六轴限位。单独诊断用 `bash "$D" limits` 会产生六帧参数查询，应在建立本次保持目标**之前**使用。

`prepare` 依次询问 OPEN、CLOSE（总开口，mm）和夹力（N）。先用尺量方块宽度，选择能够套入的 OPEN、足以夹持的 CLOSE 和经现场核实适合物体的力。首批程序限于 H0 已用过的 15–40 mm 和最高 1 N。若物体不适合该范围，换轻质方块。按提示从侧面量两指内侧间距，保留初始、张开、空夹闭合、再次张开四组尺读/反馈。每次确认动作前移开手与标尺。尺读与反馈差超过 2 mm 即中止。闭合附近的负小读数照实保留。初始同位提交有新鲜实测起点与底层发送回执；这一步不会重新使能或写零点。

如果游标卡尺净距与反馈相差超过 2 mm，原样记下这两个量。已有会话可运行 `bash "$D" width-check "$S" 25` 采一个独立测点。操作者先把工具、方块和手移出动作区，明确确认后才发送一个 25 mm 空夹目标。停稳后在两侧网纹面的相同深度量净距。程序单列差值和判定，不写教学就绪状态或训练数据。同一会话保留第一次 prepare 超差结果后，若已独立测过闭合端、中间点及重复张开端，可用 `bash "$D" prepare-pads "$S" --first-open-mm 35 --object-mm 20` 接续本次首批联调（这里的 35、20 是本会话真实尺读，其他布置采用各自实测）。该命令只接收，核对原保持位与所有中间提交。原始 SDK 状态、SDK 提交目标和卡尺净距分别留档，正式训练需要先确定全程开口的数据定义。

## 2　手拖一条完整路径

固定盘子和方块的摆放位置，给布局记名。首条用 `A01`。保持当前已张开的夹爪，运行：

```bash
bash "$D" teach "$S" A01
```

1. 等终端提示腕图已开始记录。保持起点，**单击**实体示教钮，确认绿灯常亮，再在终端按 Enter。程序读取实际示教状态。起点静止至少 1 秒。
2. 手拖到方块上方，缓慢下降，让张开的指尖包住预定夹持部位。静止 1 秒，输入 **C 回车**，再停 1 秒。此时只记闭合意图，夹爪仍张开。
3. 抬高越过盘沿，沿实际可达路线移到浅盘上方，下降到释放位。静止 1 秒，输入 **O 回车**，再停 1 秒。
4. 抬起、退回到**本次示教开始时的实测保持姿态**。看起点参照图和实时姿态。静止 1 秒，输入 **E 回车**。软件检查六轴与本次起点均在 0.35° 内，若提示未回到，仍在示教时继续微调。终端每秒显示 J1–J6 相对起点的角度差。中途如需分段，可在静止处输入 B 回车，保持该姿态，再输入 N 回车接续。原始反馈全程保存，重放前逐样本检查分段边界不超过 0.2°。新的布局重新示教。
5. 终端提示软件采集结束后，再**单击实体键**退出，亲眼确认灯灭，再回车。异常退出时也要在现场查灯和控制器状态。避免双击触发内部回放。厂家内置记录时限为 3 分钟，留足完成和退出时间。

原始轨迹、完整腕图和开合标记保存在 `$S/*_teach/`。整个示教窗口要求主机 TX 增量为 0。下一步会从完整三报文组重建路径，检查静止段、样本间隙、实际控制器/SDK 限位和首尾衔接。同一记录取首尾、抓取、释放标记作为固定节点，对其间所有采样限制逐轴路径近似误差至 0.08°。该关节路径仍需在真实布局核查间隙。

如标记高度不合适，可以撤回本次**被动手拖录制**，保留失败来源并重录。抓取位从侧面确认两指实际工作面覆盖方块侧面且指尖留有桌面间隙。如果 USB-CAN 断开过，先核对同一转接器、现场控制状态及独立关节反馈。只有已退出示教、回到此前确认的健康静止 CAN/MOVE_J 起点、手和工具已移开时，运行 `bash "$D" restart-teach "$S"`；它查询限位，从新的实测姿态重新提交同位和已核实的空夹开口，保存新接口编号与 TX 计数。随后在相同物体布局重启 `teach`。本次原始记录、旧回执和旧保持来源随会话保留。

## 3　移走方块，走一遍真实空场路线

只移走方块，固定盘子、支架和线缆。人退出动作区，能观察整条路径与现场急停。运行两条独立命令：

```bash
bash "$D" empty "$S"
bash "$D" review "$S"
```

执行前会显示规划用时。程序先检查先前实际提交的保持位、本次 boot 与主机 TX 变化；在需要切换时，复用 H0 近零灯灭→待机→CAN 的确认流程。保持位、实测姿态或控制器反馈不相符时停止。MOVE_J 档位 5%，参考速度最多 2.5°/s，逐段参考加速度上限 8°/s²，名义目标间隔 50 ms。每段沿真实路径运行；夹爪标记处先确认关节到位再发开合。普通轨迹点连续下发。

**在一段确实缓慢移动、离开桌面和盘沿的路径上，试一次 P 回车。** 等“暂停，保持已确认”，观察无继续推进或下沉，然后 **R 回车**继续。空场审核要求暂停前 0.4 秒的实测位移大于 0.1° 且已成功恢复。E 回车请求提前结束并确认当前目标保持，整条记为中断。P/E 在路径调度处受理，不能用作即时急停。遇到危险按现场物理急停。动作故障或运动时 Ctrl+C 走阻尼急停路径，机械臂可能下沉；软件提交急停也要现场确认。正常结束由程序确认到位并保持，全程不以失能作为正常收尾。

`review` 自动选该会话最近的空场/实物执行，打印质量统计、打开完整腕图回放和 `trajectory.png`。可指定终端打印过的绝对执行目录复核某一条。看盘沿净空、线缆、抓取与释放时机、实际开口和最终保持；逐通道检查目标与实测。全部符合再输入 **PASS**。未通过时输入问题和阶段，保留该次记录；若实质修改路线，重新 `teach` 并重做空场。相机图未必能拍到臂后侧，现场目视和录像都要看。

## 4　摆回方块，一次只做一条

把方块放回 A01 的原位置、朝向。每条开始前确认盘子未移、夹爪张开、没有人手在轨迹内。下面两条命令运行一次、复核一次。首批取得 3 条完整成功后先看整批，有需要再做到 5 条。

```bash
bash "$D" block "$S"
bash "$D" review "$S"
```

要亲眼看到夹起、搬运、放入盘、张开后物体留盘、空爪退回，全程无人工救场，才能输入 PASS。抓住物体时夹爪实际间距可大于闭合目标。滑脱、未进盘、碰撞、暂停或人工帮忙，都保留原始执行。已知失败可直接记录现场原因，例如：

```bash
bash "$D" review "$S" --failed '转移时滑脱，未入盘'
```

每次审核后重新把物体摆回，不要循环无人值守启动。换方块位置/朝向时使用新布局编号，在同一会话运行 `teach` 后再核查新空场。换会话时重新 `prepare`。本次保持来源若已失效，先读 `status` 并查原因；在已确认的近零、已使能 CAN/MOVE_J 起点才可新开会话。

## 5　核对动作来源并导出

```bash
bash "$D" export "${S}_commissioning" --commissioning "$S"
```

默认实物样本为 `commissioning_only`。联调导出采用 `commissioning` split，现有 reader 可按该 split 读取。正式训练入口要求独立的 `train` 记录。失败、部分下发、手拖和空场均无法进入成功导出。已有输出目录会保留，再次导出选新目录。

| 文件 | 现场复核内容 |
| --- | --- |
| 每次执行的 `run.json`、`feedback.csv` | 同机 boot_id、来源与终态；每个 0x2A5–2A7 完整有序组、0x2A8 独立反馈、接收时间、原始字节和有符号值 |
| `tx.csv`、`commands.jsonl` | 真实 send_bus.send 开始/结束、CAN ID、字节和返回/异常；请求值、源轨迹节点与插值进度、实际提交并从字节解码的目标、部分提交。主机提交和到位反馈分开 |
| `rgb/`、`rgb.csv`、`rgb_status.json` | 全部 received RGB 原图、ROS header、回调时间与写盘/队列计数。header 表示驱动时间；未经独立曝光同步验证 |
| `review.json`、`quality.json`、`trajectory.png` | 实物结果、反馈/图像年龄、三报文跨度、收图和动作间隔、提交次数、动态误差、开合和保持终态；失败的运行保留可取得的原始证据 |
| 导出的 `dataset.json`、`index.json`、`alignment_manifest.json`、每条的 `row_sources.jsonl` | 每步指回源图像、实测反馈、当前保持与未来目标的 ID、时间、年龄和有效区间 |
| 每条 episode 的四个 NPY | `state.npy`、`actions.npy`、`camera_rgb.npy`、`policy_timestamps_ns.npy`；直接供现有 `SingleCameraDataset` 读取 |

对严格 50 ms 网格起点 t，使用 t 时已收到的最后一张图、最后一组完整六轴和最后一次夹爪反馈。行标签取 (t, t+50 ms] 末端最近一次可确定的完整保持目标；边界落在三包提交过程时，退到该提交之前的最近一致时刻并记录偏移。两类目标各自持有，未发新命令的轴/夹爪使用先前真实提交的来源。保留 t 时的当前目标用于核对动态误差。10 步 chunk 由 reader 拼本 episode 的相邻行，末尾重复该 episode 最后一行。每次真实导出会通过当前 reader 核对末行行为。

## 6　首批质量确认后的正式采集

目标是 30–50 条有差异的完整成功执行。按布局和源路径重新示教、核空场，主动指定 `bash "$D" block "$S" --formal`，每一条仍要审核。正式导出接受 `export 输出目录 --train 训练会话目录… --validation 验证会话目录…`；同源轨迹、同一真实布局 ID 或同一会话不得跨 split。50 条可从 40/10 起步。两个模型共享冻结分组，各自使用实际 wrist 全参配置和 train-only 统计；π0 使用 mean/std，π0.5 使用 quantile。正式数据、训练预算和 GPU 状态齐备后再训练。

当日结束，让当前运动程序正常完成；在终端 A 结束本次启动的相机，在 B 关闭 viewer，再用 `bash "$D" status` 取得末次实测。每次现场工作把真实目录、统计、问题、解决情况和终态记入[唯一每日日志](PI_DAILY_WORK_LOG.md)。控制复用[现场 H0 修复](PI_PIPER_H_START_DIAGNOSIS_20261122.md)，标定沿用[11 月 22 日冻结文件](../results/calibration-audit/20261122/ssh_multiview/wrist_rgb_calibration.json)。
