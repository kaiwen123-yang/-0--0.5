# 研究结果发布与人工备份规则

生效日期：2026-11-03（北京时间）。来源：用户最新决定。

**GitHub只发布研究代码与分析所需的关键小文件。大检查点、完整视频和原始数据不再自动上传；由用户定期从服务器数据盘导出到自有存储盘备份，再由用户统一删除。研究与正常训练不等待大文件交付。**

本规则覆盖此前“全部大产物上传Release”“后台继续历史上传队列”“上传完成后删除服务器研究产物”和“Codex代做本机归档”等安排。实验方法、成功判据、当前研究阶段不因交付策略改变。

## 1. 后续顺序

服务器完成计算 → 推代码、实际配置、逐回合结果和结论 → 继续研究。

完整检查点、视频和原始数组先保留服务器，由用户独立安排导出备份和清理。Codex不把大文件发布作为阶段完成、启动下一阶段或提交结论的前置条件。

## 2. GitHub保留什么

| 内容 | 发布要求 |
|---|---|
| 本轮实际代码改动、启动参数、必要环境说明 | 保留，不上传已安装环境或包二进制 |
| 模型/检查点标识、累计更新数、训练/推理种子、RNG规则、resume小型元信息 | 保留，完整模型与optimizer张量仍在服务器 |
| 归一化小JSON、数据来源与划分、实际采样设置和已有小型采样表 | 保留，不重新扫描全部数据生成哈希 |
| 完整逐回合紧凑结果 | 成功和失败都保留，维持真实分母与任务身份，支持跨模型配对 |
| 正常训练曲线所需的小型日志、候选选择、简明结论 | 保留，不复制冗长控制台输出或高频全量传感器日志 |
| 直接解释当前问题的关键曲线、图或数据摘录 | 按具体分析需要提供 |
| 完整检查点、optimizer分片、完整视频、原始图像/数组/数据集 | 不自动上传Git、LFS或Release，用户自行备份 |

沿用现有run.json、node_*.json、lora_training.json、paired_comparison.json等有效记录；不为发布再建立多套报告或通用归档框架。

逐回合记录应能找到布局、目标、推理种子、成功判据、最终成功/失败、失败阶段、关键行为指标和原始产物所在路径。只给总体成功率或只挑成功案例不足以支持后续分析。

数据摘要来自实际已完成计算，不为“补完整”再训练、再评测或扫整库。需要看某个失败时，在服务器就地读取对应原始文件，优先导出关键时间窗或紧凑JSON；确实需要的少量画面/短片段按具体问题提供，不恢复全量上传。

## 3. 服务器上的大产物与用户备份

- 保留检查点、optimizer、RNG、norm、采样、数据、日志、轨迹和视频，直到用户自行处理。
- 用户按自己的节奏导出到自有存储盘。Codex不代替用户启动下载、打包、存储盘归档、备份验收或定期备份任务。
- 用户完成备份后由用户统一删除。Codex不因“任务结束”“已推Git”“已备份”自行删除研究产物；以后用户若另行授权删除，再按其明确范围执行。
- 正在训练/推理/评测及已安排续训所需的基线、数据和完整状态，即使已经备份，也应保留到不再依赖。不能形成删除后下一轮又重新下载的循环。
- Git里仅保留关键产物的实验名、检查点标识和目录位置，沿用现有记录。用户备份目录可使用相同实验名，便于之后定位；无需额外生成逐文件摘要或大清单。
- 工作环境、共享基础权重、运行/编译缓存、工作代码、Git与其他项目不动。
- 没有活动依赖的传输暂存和重复临时副本，仍可按既有临时文件清理授权处理；这不等于获得删除研究产物的权限。

GitHub负责代码、研究记录和分析证据；完整恢复依赖服务器现存资料及用户存储盘备份，不宣称GitHub单独包含全部可恢复数据。

## 4. 既有大文件队列怎么处理

1. 停止新增大检查点、完整视频、原始数据的自动上传、打包排队及自动重试。
2. 服务器Codex接续时，定位本项目实际大文件传输/压缩子任务并停止其继续执行。保留训练、模型服务、评测、数据采集和小文件Git发布。
3. 不按全部python进程、整个tmux会话或整个实验父任务粗暴终止。若上传与计算共用入口，只停用大文件发布调用路径，不停止计算或改动工作环境。
4. 尚未上传的旧项目转为“按用户新策略不再上传，由用户自行备份”。保留历史pending快照原义，不能改称上传成功，也不再把清空旧队列作为研究任务。
5. 已上传的Release资产、原始历史索引和历史删除回执保留，不擅自删除远端资产、不重写过去发生的事实。
6. 仍然需要的Git小文件推送沿用官方AutoDL学术加速；禁止服务器/电脑VPN、隧道和自动VPN回退，不改全局网络。

**本次ChatGPT仅更新GitHub规则与执行文档，当前会话未连通服务器。仓库政策已改变，不代表服务器正在运行的队列已经停止；该动作须由能访问AutoDL的Codex落实并记录实际结果。**

## 5. 不新增的工作

不做哈希/校验和扫描、回下载验证、恢复演练、冒烟/shape/mock/单元测试、全参数差分、备份验收流水线或全库重构。不因为改变发布规则再运行模型。只修改当前实际调用路径里与大文件发布有关的部分，继续原定研究任务。
