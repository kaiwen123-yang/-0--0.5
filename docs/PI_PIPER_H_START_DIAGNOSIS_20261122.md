# Piper H 零端越界与阻尼急停诊断

2026-11-22，第二开发平台。13:41 的 J2 −3.172°、J3 +0.207° 是控制器实际发出的反馈。六驱动当时均失能，J2、J3 的电机反馈电流均为零。11 月 21 日的发送日志另证实，H0 在一次取样姿态到位超时后主动发送了阻尼急停，随后关节位置有明显变化。已修正这一软件触发条件。现场是否碰桌、机械限位与编码器基准是否存在偏差，尚无独立测量结论。

独立解析失能窗口的原始字节后，0x2A5/0x2A6 各 402 帧给出 J2 −3.172°、J3 +0.207°。0x252/0x253 各 201 帧的电机位置分别为 −0.055 rad 和 +0.003 rad，折合 −3.151°、+0.172°。驱动电流均为 0 A。两路都报告相同方向，足以排除单纯的主机显示或关节包符号读反。它们仍来自同一机器人，不能代替外部角度基准。使能零位时，关节包为 0°，电机位置则为 J2 +0.011 rad、J3 −0.007 rad。故不能以两个数值字段严格相等作为零点正确性的判据。[原始包计数、范围和状态](../results/calibration-audit/20261122/start_limit_diagnosis/can_evidence.json)

厂家对 0x150 阻尼急停说明了重力下的缓慢下落；这与昨晚的角度变化一致。两日之间缺少连续编码器、外部测角与接触记录。现有证据可定位 H0 的触发原因，不能单独证明重力造成了次日所见的全部偏差，也不能判定编码器故障。现场再次遇到同样读数时，最有区分力的是在有可靠支撑、已知机械基准的位置同时比对关节读数、电机读数与基准标记。若在可重复的同一机械基准仍有相同偏差，应将本机固件版本、照片和原始读数交给厂家核对零点及结构件。正常停放按手册先运动回零，再断电。[厂家关于阻尼急停的说明](https://github.com/agilexrobotics/piper_sdk/issues/20)

## 已部署的修复和验收范围

正常到位仍要求目标误差在 0.5° 内、控制器确认到位并持续静止。普通单姿态等待超时后，H0 仍拒绝该姿态并返回失败。它增加了下列两种有实测数据支持的处理：

- 若控制器已确认原目标、关节读数在目标附近轻微跳变，另用各电机实际位置的连续 0.5 s 静止窗核对。经核实后保留当前已确认的位置目标。
- 若仍未确认原目标，只有六驱动健康、CAN/MOVE_J、目标附近且在限位内、关节和电机位置持续静止时，才发送一次当前实测位置。新报文之后须重新收到到位和静止反馈。保持结果单独写入，原目标不计成功，路线停止。
- 出现驱动故障、输入急停、运动偏差、反馈不新鲜或保持失败时仍走原有急停处理。校准程序不会自动复位、重新使能或继续下一点。手册规定的紧急处置保留。这是项目对普通取样超时的应用层处理。

原代码在 a01 的实测静止数据回放中走到阻尼急停。补丁部署到第二平台实际入口 `~/research/dog-and-arm/scripts/h0_operator_motion.py`；发布分支基于较新的现场分支，保留了该分支原有的失能模式切换功能。16 个离线回归场景覆盖正常、未确认目标、到位后近零跳变、输入急停、碰撞、数据过期、运动继续、保持发送失败和异常失能起点。回放使用现场数据及合成的故障/确认分支，不把测试替身当成当晚 u11 的完整原始轨迹。[H0 修复及回归夹具](https://github.com/kaiwen123-yang/dog-and-arm/commit/cf01b434011db7c443e2fc88b3b458dc280ef984) · [回归结果](../results/calibration-audit/20261122/start_limit_diagnosis/replay_results.jsonl)
