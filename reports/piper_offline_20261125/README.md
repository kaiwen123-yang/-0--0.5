## 如何重建与追溯

1. 来源合同固定 revision、源字段名、物理证据边界、腕图键、时钟和维数。A、C 用 frame_index/30 的有理数名义时间（保存原 float32 时间）。B 用发布的 real_observation_timestamp_s 相对起点，并同时保存 observation/action 的墙钟 ns 和原始秒值。B 的时间列是发布观测记录时钟，缺少逐设备曝光或反馈包的原始时刻。图像取冻结解码审计已经验证的 presentation PTS。以各自首帧为原点，将 PTS 换算到同一回合轴；不声称真实传感器同步。所有秒值转整数 ns 时四舍五入，精度为 1 ns。
2. 保留连续 50 ms 查询网格。state、image、future_state 各自在相应的源时轴上取不晚于查询边界的最后一个记录。保留两路原始 index 和实际时间、图像帧与 PTS、查询年龄、实际跨度、重复/缺失/间隙/过时/填充标志。B 的源 action 与下行 state 在 129,112 个相邻行对逐维相等，直接在 state 时钟上查询新目标。末行若没有支持 t+50 ms 的后续观测，标记 missing，保留查到的最后行作为追溯指针，future_state 置 NaN。无插值、绝对值裁剪或事先 delta。
3. 选用 **40 ms** 作为约 30 Hz 来源的保守区间断点（比通常 33.3 ms 多约 20%），与本机原过滤各自独立。B 有 9 条触发，共排除 9 个有未来样本的网格行；实际最大相邻观测间隔约 45.25 ms，没有超过 50 ms 的缺口。若仅用 50 ms 断点将得到 81,277 个 B 起点；采用 40 ms 后为 81,199。371 号在源行 22→23 处分段，有效起点闭区间为 0–5、16–174。没有把中间坏点删除后重新编号或连接。其他 B 任务中存在的更大跳变没有外推到叠碗数据。
4. 一步需要有更新的未来源观测，十步须逐步有效且起终源记录同属一个区间。A/C 的实际一步跨度分别为约 33.333、66.667 ms，A 各 50,000、49,907 行，C 各 9,260、9,221 行；B 有实际采样抖动，跨度为 27.94–71.86 ms。动作块十个名义查询时距仍为 50–500 ms。各来源的图像和观测行均无跨网格重复使用。含无效末行在内，A 有 107 行、C 有 39 行再次指向上一个目标源行，这些尾行没有进入有效标签。[年龄、跨度与重复计数](timing_summary.csv)

   新数组把源 state、源原始 action、新的未来绝对状态分开存；B 保留全 14 维。只在单腕源内诊断读取时投影前七维。每回合 source.json 与 grid.npz 共同给出从单个起点回原件的路径。
5. 默认有效训练/验证仍为本机 40/10。外部完整候选整条进入 prospective train 池；A 缺采集会话身份，保守地把整个发布批次放同侧，B 全部观测起始墙钟落在 2026-04-13 UTC，同样整批放一侧。没有另造来源独立验证比例或伪造采集会话。本机 session、placement、source_trajectory 三种分组均做了交叉检查。复用原件重复项审计；另将 V01 的 3,229 个非全保持、无填充窗口与本机 train 的 11,899、A 候选的 52,429、B 候选的 5,960 个同口径窗口逐一比对，当前七维状态加十步目标均无逐字节重合。该检查能发现等值裁剪，无法排除改变坐标或时间尺度的近似复录。[跨划分检查](split_check.json)
